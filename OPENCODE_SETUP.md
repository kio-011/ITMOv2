# OpenCode: установка и подключение модели

Во всех трёх практиках OpenCode создаёт и изменяет файлы, выполняет команды и ведёт журналы. Работайте в режиме Build: ставьте задачи в чате и проверяйте diff. Режим только для чтения используется в отдельных тестовых запусках, ответы которых сохраняет рабочий агент.

Официальная документация: <https://opencode.ai/docs>.

## 0. Свой форк

1. Откройте студенческий репозиторий и нажмите **Fork**.
2. Клонируйте форк из своего GitHub-аккаунта:

   ```bash
   git clone https://github.com/<ваш-логин>/ITMOv2.git
   cd ITMOv2
   git remote -v
   ```

3. В `origin` должен быть ваш GitHub-логин. Все изменения и PR делаются из этого форка.

## 1. Установка

Выберите один способ.

macOS или Linux:

```bash
curl -fsSL https://opencode.ai/install | bash
```

Если уже установлен Node.js:

```bash
npm install -g opencode-ai
```

macOS через Homebrew:

```bash
brew install anomalyco/tap/opencode
```

Windows: используйте WSL, затем выполните команду для Linux.

Проверка:

```bash
opencode --version
```

## 2. Подключение VseLLM

1. Получите у преподавателя учебный VseLLM API key. Не пересылайте его другим студентам и не публикуйте.
2. Конфигурация VseLLM уже находится в [`opencode.json`](opencode.json) в корне форка. Ключ подставляется из переменной окружения; редактировать JSON вручную не требуется.

3. В текущем терминале задайте ключ:

   ```bash
   export VSELLM_API_KEY='ваш-ключ-vsellm'
   ```

   Запустите OpenCode:

   ```bash
   opencode --agent build
   ```

4. Если OpenCode предложит подключить провайдера через `/connect`, выберите `VseLLM` и вставьте API key. Затем выполните `/models` и выберите модель, указанную преподавателем.

Проверка сохранённого провайдера:

```bash
opencode auth list
```

OpenCode хранит credential вне репозитория, в пользовательском файле `~/.local/share/opencode/auth.json`. Не копируйте этот файл и не добавляйте API key в `.env`, Markdown, скриншоты, commit или PR. Общий `opencode.json` содержит только ссылку на переменную окружения и хранится в репозитории. Ключ в него не записывайте.

## 3. Быстрая проверка

```bash
opencode run "Ответь одним словом: READY"
```

Если модель не выбрана, вернитесь в TUI, выполните `/models` и выберите доступную модель VseLLM.

## 4. Эксперименты первой практики

Рабочая сессия Build остаётся в корне форка. Она готовит отдельные запуски, сохраняет ответы и обновляет `practices/practice_01/prompts.md`.

Поручите агенту:

1. Создать временную папку вне репозитория и скопировать в неё только `TRAINING_PR.diff`.
2. Передать конфигурацию провайдера через `OPENCODE_CONFIG`, а запрет инструментов тестируемой модели — через `OPENCODE_CONFIG_CONTENT` с `{"permission":{"*":"deny"}}`.
3. Выполнить в этой папке `opencode run --agent plan --model <выбранная-модель> --format json --file TRAINING_PR.diff -- "Ниже diff учебного PR. Посмотри PR и найди проблемы."`. Модель берётся из вашего выбора в `/models`.
4. Сохранить фактический ответ в `practices/practice_01/results/`, без внутренних рассуждений, и записать запрос, модель и ссылку на ответ в журнал как `P1-01`.
5. Обсудить с вами результат. Рабочий агент собирает контекст и master prompt и записывает их в файлы по вашим замечаниям.
6. Выполнить второй новый запуск с той же моделью и настройками. К тому же diff добавить согласованный master prompt со встроенным контекстом. Ответ сохранить как `P1-02` и записать в журнал ваше сравнение.

Запрет инструментов действует только на тестовый процесс. Рабочий Build должен иметь возможность сохранять ответы и редактировать документы. Не передавайте тестовым процессам историю рабочего чата или эталонные ответы.

Описание режимов: [агенты OpenCode](https://opencode.ai/docs/agents/). Параметры запуска и формат событий: [CLI](https://opencode.ai/docs/cli/). Подключение конфигурации: [Config](https://opencode.ai/docs/config/).

## 5. Если что-то не работает

- `opencode: command not found` — перезапустите терминал и повторите `opencode --version`;
- провайдер не виден — проверьте `opencode.json`, переменную `VSELLM_API_KEY`, затем повторите `/connect`;
- модель недоступна — откройте `/models` и выберите доступную преподавателю и группе;
- рабочий OpenCode просит разрешение на запись или shell — проверьте, что действие относится к заданию; эти операции нужны для файлов и проверок. У тестового процесса инструменты запрещены конфигурацией;
- токен случайно попал в файл или PR — немедленно удалите его из публикации и отзовите ключ в VseLLM.
