03 — MCP · Postgres

Агент видит
настоящую схему базы

MCP-сервер — отдельная программа, которую Claude Code запускает при старте сессии. Она подключается к базе subtracker и отдаёт агенту 5 tools: query, schema, table_info, explain, list_schemas.

Зачем подключеноБез MCP агент пишет запросы по памяти о том, как таблицы «должны» называться. С MCP он читает фактическую схему — и ошибается на именах колонок на порядок реже.
{
  "mcpServers": {
    "postgres": {
      "command": "node",
      "args": ["tools/mcp-pg/node_modules/mcp-pg-server/dist/index.js"],
      "env": { "DATABASE_URL": "postgres://subtracker:…@localhost:5432/subtracker" }
    }
  }
}

Один сервер ≠ один tool. Сервер — это процесс, который публикует набор инструментов; сколько их, решает автор сервера. Отсюда пять tools от одной записи в конфиге.

Пакет оказался сломан

Починка
вместо подмены

Опубликованный mcp-pg-server@1.0.0 не запускался на Node v26: в собранном dist/index.js дважды записан shebang, вторая строка уходит в парсер как код.

SyntaxError: Invalid or unexpected token
  at dist/index.js:2
  #!/usr/bin/env node   ← дубль

Вместо замены на другой пакет — локальная обёртка tools/mcp-pg/, которая ставит зависимость и срезает лишнюю строку на postinstall.

Почему такПравило задания — не подменять похожим молча. Проблема воспроизводимая и чинится в три строки, значит чиним и фиксируем, а не ищем другой пакет.
04 — Hook · PreToolUse

Хук, который не даёт тронуть секреты

AGENTS.md запрещает править и коммитить .env. Запрет в тексте работает, пока агент о нём помнит. Хук делает его обязательным: скрипт запускается до каждого вызова инструмента, и запись в файл секретов не происходит вовсе.

Конфигурация

{ "hooks": { "PreToolUse": [{
  "matcher": "Write|Edit|Bash",
  "hooks": [{
    "type": "command",
    "command": "python3 \"$CLAUDE_PROJECT_DIR/.claude/hooks/protect_env.py\""
  }]
}]}}

Скрипт читает полезную нагрузку хука со stdin: tool_input.file_path для Write/Edit и tool_input.command для Bash. Выход с кодом 2 отменяет вызов, а текст из stderr уходит агенту как причина отказа.

Что блокируется, а что нет

запись .env.env.local.env.production echo >> .env через Bashsed -i · tee · cp · mv · rm
.env.example.env.sample.env.template чтение: cat · grepлюбые другие файлы
Честная границаПроверка Bash идёт по тексту команды и обходится хитрой конструкцией. Это защита от случайной записи, не от злого умысла. Чтение .env хук не ограничивает — для этого нужен permissions.deny, он не настраивался.

Свой skill — prompt-rctf

2 балла

Задача была найти не проектный скилл, а тот, которым пользуешься каждый день. Схему RCTF — Role, Context, Task, Format — я и так пишу руками постоянно, и каждый раз теряются одни и те же вещи. Скилл превращает сырую просьбу в готовый промпт, а скрипт детерминированно ловит типовые провалы формы.

Контракт

Что на входе и что на выходе

Вход — сырая просьба. Выход — текст промпта одним блоком кода, который копируется в любую LLM. Задачу из промпта скилл намеренно не выполняет — иначе вместо инструмента получается просто ответ на вопрос.

  • Role — одно предложение, специальность и уровень. Без регалий.
  • Context — факты, ограничения, что уже пробовали. Длинный материал вставляется целиком внутри тега, а не пересказывается.
  • Task — ровно одно действие, с глагола, с измеримым признаком готовности.
  • Format — конкретная структура и объём; что в ответе быть не должно.
---
name: prompt-rctf
description: Собирает из сырой просьбы готовый промпт по схеме
  RCTF… Применять, когда просят «составь промпт», «улучши промпт»,
  «как правильно спросить у нейросети». Выдаёт только текст промпта
  и не выполняет задачу из него. НЕ применять, когда задачу надо
  просто сделать.
---

Доказательная база

Почему роль —
одно предложение

Практические статьи советуют назначать модели развёрнутую экспертную персону. Эмпирика это не подтверждает — и именно здесь скилл расходится с популярными советами.

  • 162 персоны, 4 семейства моделей, 2410 фактических вопросов — прироста относительно контроля без персоны не обнаружено arXiv:2311.10054
  • Экспертная роль даёт нулевой или небольшой плюс, но нерелевантные детали в её описании роняют качество почти на 30 п.п. arXiv:2508.19764
  • Остальные правила — по систематическому обзору The Prompt Report: 1500+ статей, таксономия 58 приёмов arXiv:2406.06608
Честно про сам акроним RCTF в рецензируемой литературе не встречается — он из практических материалов и бытует в вариантах RCTF, RTCF, RTF. Это мнемоника, чтобы ничего не забыть, а не проверенный в экспериментах метод. Доказательная база есть у отдельных приёмов внутри него. Это записано прямо в sources.md.

Свой MCP — ticktick-deadlines

2 балла

Сервер подключается к моему настоящему TickTick и отвечает на вопрос, которого обычный таск-менеджер не решает: не «что раньше по дате», а «что горит сильнее». Для этого к каждому дедлайну хранится оценка трудоёмкости в часах, и задачи сортируются по нагрузке — сколько часов в день придётся тратить, чтобы успеть.

Идея

Почему по часам,
а не по дате

Список по дате врёт. Задача на завтра, до которой час работы, менее опасна, чем задача через два дня, до которой девять часов. Сортировка по часы ÷ дни показывает это сразу.

def pressure(hours_needed, days_left):
    if days_left < 0:
        # просроченное всегда выше любого будущего
        return OVERDUE_BASE + (-days_left) * 10 + hours_needed
    return hours_needed / max(days_left, 1)
Строка про OVERDUE_BASE появилась из-за упавшего тестаДо неё просроченная задача оценивалась ниже, чем большая задача с запасом времени: assert 2 > 24.0. Это была настоящая ошибка в формуле, а не в тесте.

Чего стоило подключение

Три грабли, не описанные в документации

  • Приложение перетирает собственный конфиг. Правка исчезала несколько раз подряд: запущенное приложение сохраняет настройки из памяти поверх файла. Лечится только выходом перед правкой.
  • Голое python3 в command не находится — у приложения другой PATH. Нужен полный путь /usr/bin/python3.
  • Рабочая папка при запуске не определена — все пути в args абсолютные, а файлы рядом сервер ищет через Path(__file__), не через Path(".env").
Цена в контексте — замерена 4 tools этого сервера = 1723 символа описаний ≈ 574 токена. Это не разовая плата: описания едут с каждым запросом, пока сервер подключён. Десяток подключённых серверов — заметный кусок окна, потраченный на инструменты, которые в текущей задаче не нужны.

Главное

Самое полезное ограничение в задании — «не подменяй похожим молча»

Репозиторий со скиллами отдавал 404. Соблазн взять похожие из другого места был прямой, и без этого правила я бы так и сделал, а в отчёте написал «установлено восемь скиллов».

Сейчас в отчёте написано, что три не установлены и почему, с оговоркой про неоднозначность 404. Это честнее и при этом полезнее: видно, где проходит граница проверенного.

На OAuth к TickTick ушло несколько кругов: не тот скопированный URL, незарегистрированный redirect_uri, несовпадение с зарегистрированным значением. А в документации сервиса лежал персональный токен, который закрывал задачу сразу.

Дорогим оказался не протокол, а то, что страница не была дочитана до конца перед началом.

Мелкое, но показательноеВ zsh переменная path связана с PATH. Использовал path= как имя переменной цикла — получил command not found: bash. Полчаса на ошибку, не имеющую отношения ни к хукам, ни к MCP.
Открытым текстом

Что осталось незакрытым

  • Три скилла из недоступного репозитория не установлены — заменять похожими не стал.
  • permissions.deny на чтение .env обсуждался, но не добавлен: хук закрывает только запись.
  • В .mcp.json проекта какое-то время лежал дубль сервера ticktick, который уже подключён на уровне приложения, — по моим же заметкам это грабли, запись убрана.
  • В prompt-rctf раздел «Материалы курса» остался заглушкой: своей шпаргалки по лекции я туда ещё не положил. Примеры в examples.md написаны мной и покрывают четыре случая — под другой набор задач их стоит заменить.
