# Заготовки блоков

Брать как основу и подставлять свои детали. Это не шаблоны на все случаи: если заготовка не подходит, писать своими словами.

## Role

| Тип задачи | Формулировка |
|---|---|
| Объяснить тему | `Преподаватель <предмет>.` |
| Код | роль не нужна, задача фактическая |
| Проверить текст | `Редактор. Правишь смысл и структуру, не только орфографию.` |
| Разобрать требования | `Аналитик. Читаешь требования буквально и отмечаешь неоднозначности.` |
| Занятие с учеником | `Репетитор по <предмет> для <класс или уровень>.` |

Чего не писать: «гениальный», «мирового уровня», «с 20-летним опытом», «лучший эксперт». Подтверждения — `sources.md`, группа 2.

## Context: что стоит указать

- Кто я и какой у меня уровень в этой теме.
- Зачем результат нужен и кто его будет читать.
- Что уже сделано или пробовал.
- Ограничения: срок, объём, инструменты, чего делать нельзя.
- Исходный материал целиком внутри тега `<материал> ... </материал>`.

## Task: глаголы

`составь`, `сравни`, `найди`, `перепиши`, `проверь`, `объясни`, `переведи`, `сократи`, `разбей`, `оцени`

Одно действие на промпт. Если тянет написать «и ещё», это второй промпт.

## Format

| Нужен результат | Формулировка |
|---|---|
| Таблица | `Таблица с колонками: <перечислить>. Строк не больше N.` |
| Список | `Список из N пунктов, каждый до одного предложения.` |
| Текст | `До N слов. Без вступления и выводов в конце.` |
| Код | `Один файл <имя>. Без комментариев. Только код, без объяснений.` |
| Данные | `JSON по схеме: {"поле": тип}. Без markdown вокруг.` |
| План | `N этапов, у каждого: действие, результат, время.` |
| Сравнение | `Таблица: вариант, плюсы, минусы, когда выбирать.` |

Полезные ограничения в конце Format: `Не добавляй вступление.` `Не пересказывай задание.` `Если данных не хватает — напиши, каких, и остановись.`

## Примеры (few-shot)

Когда формат жёсткий, добавить 2–5 пар:

```
Примеры:
Вход: <пример входа>
Выход: <пример желаемого выхода>

Вход: <другой пример, не похожий на первый>
Выход: <...>
```

Примеры должны отличаться друг от друга и покрывать краевые случаи, иначе модель скопирует частность.
