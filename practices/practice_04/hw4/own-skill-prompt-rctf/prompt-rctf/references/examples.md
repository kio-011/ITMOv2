# Примеры

Пары «сырая просьба → промпт». Для каждой показан слабый вариант и исправленный, чтобы было видно, чем они отличаются.

---

## 1. Учёба: разобраться в теме

**Сырая просьба:** объясни мне нормальные формы в базах данных

### Слабо

```
Role: Ты гениальный преподаватель баз данных с 20-летним опытом, лучший в своей области.
Context: Мне нужно разобраться в теме.
Task: Объясни нормальные формы, приведи примеры и расскажи, зачем это нужно.
Format: Объясни подробно и качественно.
```

Что не так: роль с украшениями (убирает только место, пользы не даёт), контекст пересказывает задачу и не содержит фактов, в Task три действия сразу, Format не задаёт ничего измеримого.

### Исправлено

```
Role: Преподаватель баз данных.

Context: Я студент, знаю SQL на уровне SELECT с JOIN, с проектированием схем не работал.
Готовлюсь к экзамену, нужно понимать, а не заучивать. Нормализацию раньше не изучал.

Task: Объясни первые три нормальные формы на одном сквозном примере таблицы заказов,
показывая, какая проблема решается переходом к каждой следующей форме.

Format:
- Три раздела, по одному на форму.
- В каждом: таблица до, в чём проблема, таблица после, одно предложение вывода.
- Всего до 500 слов. Без вступления и без списка литературы.
```

## 2. Код: написать тесты

**Сырая просьба:** напиши тесты для эндпоинта статистики

### Исправлено

```
Context: Проект на FastAPI. Эндпоинт GET /api/stats/summary возвращает месячный и годовой
итог по активным подпискам пользователя. Стек: async SQLAlchemy, httpx ASGITransport,
sqlite in-memory, общие фикстуры лежат в tests/conftest.py. Деньги хранятся в Decimal.

<код эндпоинта>
...сюда вставить файл целиком...
</код эндпоинта>

Task: Напиши тесты на три случая: суммируются только активные подписки, пустой список даёт
нули, пользователь не видит чужие подписки.

Format:
- Один файл tests/test_stats.py.
- Каждый случай — отдельная async-функция с говорящим именем.
- Ассерты на status_code и на тело ответа. Без комментариев в коде.
```

Роли нет намеренно: задача фактическая, персона тут не помогает (`sources.md`, группа 2).

## 3. Разбор задания по критериям

**Сырая просьба:** помоги понять, что хотят в этой домашке

### Исправлено

```
Context: Ниже текст задания с критериями оценивания. Я уже сделал первый пункт.
Сдавать через неделю.

<задание>
...текст критериев целиком...
</задание>

Task: Составь чек-лист того, что нужно сдать, чтобы получить максимум баллов.

Format: Таблица с колонками: пункт, что именно сдать, сколько баллов, сделано или нет.
Строки — ровно по пунктам из задания, ничего не добавлять от себя.
```

Почему материал вставлен целиком и обёрнут тегом: пересказ теряет формулировки, а тег отделяет данные от инструкции.

## 4. Объяснить тему другому человеку

**Сырая просьба:** надо объяснить ученику рекурсию

### Исправлено

```
Role: Репетитор по программированию.

Context: Ученик 10 класса, пишет на Python циклы и функции, рекурсию видит впервые.
На прошлом занятии путался в том, что функция может вызывать сама себя.
Любит разбирать на бытовых примерах.

Task: Составь план одного занятия на 40 минут по теме рекурсии.

Format:
- Пять этапов с таймингом.
- Для каждого: что говорю, что показываю на экране, какой вопрос задаю ученику.
- Готовых решений задач не приводить, только условия.
```

## Что чаще всего ломается

| Признак | Как чинить |
|---|---|
| «подробно», «качественно», «как можно лучше» | заменить числом или структурой |
| в Task несколько действий через «и» | оставить одно, остальное отдельными промптами |
| Context пересказывает Task | вписать факты: кто, что уже сделано, ограничения |
| роль с регалиями | сократить до специальности или убрать |
| материал пересказан своими словами | вставить исходный текст в тег |
