# prompt-rctf

Вход — сырая просьба. Выход — готовый промпт из четырёх блоков, который пользователь копирует куда хочет.

## Контракт вывода

- Промпт выдавать одним блоком кода, чтобы копировался целиком.
- После промпта — не больше трёх строк: какие допущения сделаны и что стоит уточнить.
- **Задачу из промпта не выполнять.** Если пользователь потом скажет «выполни», тогда выполнить.
- Язык промпта — язык исходной просьбы.
- Не придумывать факты. Чего не знаешь — либо спроси, либо помечай как допущение прямо в промпте.

## Порядок работы

1. Выписать, что уже известно по каждому блоку, и чего не хватает.
2. Если переданы файлы или пути — прочитать их и брать факты в Context оттуда, а не по памяти.
3. Если без данных нельзя сформулировать Task или Format — задать не больше трёх вопросов одним сообщением. Не спрашивать то, что можно разумно принять по умолчанию: такое просто пометить как допущение.
4. Собрать промпт по правилам ниже.
5. Проверить скриптом (раздел «Проверка»), исправить найденное, показать только финальную версию.

## Правила блоков

### Role

- Одно предложение: специальность и уровень. Ничего лишнего.
- Убирать украшения: «гениальный», «мирового уровня», «с 20-летним опытом», «лучший в своей области».
- Если задача фактическая (посчитать, найти, проверить, извлечь) — роль можно не писать вовсе.

Почему так: в экспериментах персона в системном промпте не улучшает результат на фактических задачах, а лишние детали в описании роли заметно роняют качество. Подробности и ссылки — `references/sources.md`.

### Context

Самый важный блок: модель не может использовать то, чего ей не дали.

- Факты, ограничения, что уже пробовали, чего делать нельзя, для кого результат.
- Не пересказывать Task другими словами.
- Длинный материал (текст лекции, код, критерии задания) вставлять целиком внутри тега, а не пересказывать:
  `<материал> ... </материал>`. Разметка тегами помогает модели отделить данные от инструкций.

### Task

- Ровно одно действие. Если действий несколько — выбрать главное, остальное вынести в отдельные промпты.
- Начинать с глагола: «составь», «сравни», «найди», «перепиши».
- Указать измеримый признак готовности: по чему будет видно, что задача выполнена.

### Format

- Конкретная структура: таблица с названными колонками, список из N пунктов, JSON по схеме, файл с таким-то именем.
- Объём: число слов, пунктов, строк, абзацев.
- Чего быть не должно: вступлений, извинений, пересказа задания.

### Примеры (по желанию, но сильно помогают)

Если формат жёсткий, добавить 2–5 пар «вход → выход». Few-shot — один из самых надёжных приёмов, см. `references/sources.md`.

## Режим разбора

Если пользователь даёт уже готовый промпт и просит улучшить: прогнать его через скрипт, назвать слабые места по блокам, показать исправленную версию. Исходные формулировки не выбрасывать молча — сказать, что и почему изменено.

## Проверка

```
python3 scripts/check_prompt.py prompt.md
cat prompt.md | python3 scripts/check_prompt.py -
```

Скрипт проверяет структуру и типовые провалы формы, а не смысл. Его замечания — повод переписать блок. Код возврата: 0 — ошибок нет, 1 — есть.
