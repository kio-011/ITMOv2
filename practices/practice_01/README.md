# Практика 1. Подготовка SDLC и инженерного контекста

**Формат:** обсуждение в командах по 3–4 человека, 90 минут. Каждый студент работает в своём форке и открывает собственный PR.

**На паре:** все работают с одним [учебным diff `TRAINING_PR.diff`](TRAINING_PR.diff). Искать отдельный GitHub PR с кодом не нужно.

**Цель:** научиться собирать master prompt для AI-агента из продуктовых и технических артефактов.

**Результат:** каркас связанных SDLC-артефактов, Context Pack для одной задачи и первая версия master prompt в `prompts.md`.

## Как работать

Все файлы, включая `prompts.md`, создаёт и изменяет OpenCode в режиме **Build**. Вы ставите задачу в чате, отвечаете на вопросы агента и проверяете diff. Замечания к тексту, диаграммам и тестам также передавайте в чате. Заполнять Markdown вручную не требуется.

Начальный запрос после подключения OpenCode:

```text
Помоги выполнить Практику 1 по practices/practice_01/README.md.
Создавай и редактируй файлы сам. Уточняй у меня сведения о проекте,
которых нет во входных данных. Записывай выполненные запросы и результаты
в prompts.md. Мою оценку результата получай из диалога.
После каждого этапа показывай diff и способ проверки.
```

Рабочий агент ведёт документы и запускает команды. Два эксперимента с ревью diff он выполняет отдельными запусками OpenCode, чтобы не передавать им историю рабочего чата. Их ответы агент сохраняет в файлы и затем использует для журнала.

## До начала

1. Сделайте форк студенческого репозитория в свой GitHub-аккаунт и клонируйте его.
2. Получите у преподавателя учебный токен и настройте [OpenCode](../../OPENCODE_SETUP.md).
3. Убедитесь, что `origin` указывает на ваш форк:

   ```bash
   git remote -v
   ```

4. Попросите OpenCode создать ветку для первой практики от `main`. Команды для агента:

   ```bash
   git switch main
   git pull --ff-only origin main
   git switch -c practice_01
   ```

5. Попросите OpenCode проверить материалы из корня репозитория:

   ```bash
   make step1
   ```

Для эксперимента используйте `TRAINING_PR.diff`. Свою работу вы сдадите отдельным PR по инструкции ниже.

## Что вы сдаёте

Поручите OpenCode подготовить следующие файлы:

| Файл | Что в нём должно быть |
|---|---|
| [`context.md`](context.md) | AS IS: продуктовый и командный контекст, источники и ограничения |
| [`problem.md`](problem.md) | пользователь, проблема и измеримые продуктовые метрики |
| [`analysis.md`](analysis.md) | AS IS и TO BE процесса в выбранной нотации |
| [`product_management.md`](product_management.md) | use cases, user stories и сценарии |
| [`project_management.md`](project_management.md) | инкременты, роли людей/AI и план поставки |
| [`adr.md`](adr.md) | архитектурное решение и Mermaid-схема |
| [`tests_unit.md`](tests_unit.md) | unit-проверки |
| [`tests_integration.md`](tests_integration.md) | integration-проверки |
| [`tests_load.md`](tests_load.md) | нагрузочные проверки и ожидаемые пределы |
| [`tests_e2e.md`](tests_e2e.md) | сквозные сценарии |
| [`prompts.md`](prompts.md) | запросы, результаты, ссылки на изменённые артефакты и собственная оценка |

В каждом содержательном файле есть короткий раздел «Как использовали AI». Агент записывает в него назначение запроса, тип промпта, ссылку на строку в `prompts.md` и результаты проверки, которые вы обсудили в чате.

## Маршрут занятия

### 0–5 минут. Цель и учебный кейс

Разберите вход и выход практики. Учебный кейс — AI-помощник code review, а итоговый навык — подготовка master prompt для будущего проекта.

### 5–20 минут. Форк и OpenCode

Откройте свой форк, подключите выданный VseLLM-токен, выберите указанную преподавателем модель и получите ответ `READY`.

### 20–32 минуты. Повторение стилей промптинга

Пройдите zero-shot, few-shot, RCTF, Tree of Thoughts, Chain of Verification, ReAct, Chain of Thought и master prompting. На первой практике используется zero-shot как baseline, а затем собирается master prompt.

### 32–42 минуты. Запуск 1: zero-shot

Следуйте разделу [«Запуск 1: только diff»](#запуск-1-только-diff) ниже. У всех один вход — `TRAINING_PR.diff`. Попросите рабочего агента сохранить результат как `P1-01`. Обсудите с ним, что тестируемая модель придумала или не смогла доказать.

### 42–52 минуты. Что отсутствует во входе

Обсудите с OpenCode пользователя, проблему, границы задачи и ожидаемый результат. Поручите агенту записать согласованные сведения в `context.md` и `problem.md`. На паре достаточно основных разделов этих файлов.

### 52–65 минут. Master prompt и Context Pack

Попросите OpenCode собрать в `prompts.md` структуру master prompt: цель и роль, входы и источники, задача и артефакты, формат, границы действий, рабочие шаги, проверки и Definition of Done. Context Pack — только факты, правила, примеры и ограничения внутри этой структуры.

### 65–75 минут. Соберите первую версию

Попросите OpenCode включить в master prompt согласованный контекст, ожидаемый формат, примеры и способ проверки. Проверьте, что агент не представил свои предположения как требования проекта.

### 75–85 минут. Запуск 2: master prompt

Повторите задачу на том же `TRAINING_PR.diff` и той же модели, но передайте master prompt с Context Pack. Рабочий агент сохраняет результат как `P1-02`.

### 85–90 минут. Сравнение

Сравните два ответа по доказательности, границам действий и воспроизводимым проверкам. После пары работу проверят ревьюеры курса в вашем PR.

## Учебный кейс: AI-помощник ревьюера PR

Вход для обоих запусков — [`TRAINING_PR.diff`](TRAINING_PR.diff). Рабочий агент сохраняет результаты в [`prompts.md`](prompts.md), а согласованный контекст — в [`context.md`](context.md).

### Запуск 1: только diff

Поручите рабочему агенту выполнить отдельный `opencode run` с выбранной моделью. Для этого тестового запуска доступ к инструментам закрыт, а вход содержит только `TRAINING_PR.diff` и запрос:

```text
Ниже diff учебного PR. Посмотри PR и найди проблемы.
```

Агент должен запустить тест в отдельной временной папке без инструкций и автоматического контекста репозитория. Конфигурацию провайдера он передаёт явно. В [инструкции OpenCode](../../OPENCODE_SETUP.md#4-эксперименты-первой-практики) описан порядок запуска и сохранения результата.

После ответа обсудите с рабочим агентом слабые места результата и недостающие сведения. Он добавляет в `prompts.md` строку `P1-01`: инструмент и модель, исходный запрос, ссылку на ответ и вашу оценку. Оценку он записывает из ваших сообщений.

Если запуск не удался, агент сохраняет ошибку. Обратитесь к преподавателю и повторите запуск после исправления доступа.

### Что такое master prompt

Master prompt — инструкция для выполнения задачи AI-агентом. Он отвечает на восемь вопросов:

1. Какова цель и в какой роли работает агент?
2. Какие входы и источники ему доступны?
3. Что именно нужно сделать и какие артефакты вернуть?
4. В каком формате давать результат?
5. Какие действия разрешены и запрещены?
6. По каким шагам работать и когда остановиться?
7. Как проверить утверждения и результат?
8. По каким признакам задача считается законченной?

Context Pack — часть master prompt с фактами, правилами, примерами и ограничениями для одной задачи.

### Материалы для Context Pack

После первого запуска обсудите с OpenCode, какой информации не хватило. Используйте сведения о своём проекте и материалы, которые можете подтвердить источником. Неизвестные требования агент отмечает как вопросы к вам.

#### Задача помощника

Для одного PR помощник получает diff и возвращает:

1. краткое описание изменения;
2. не больше трёх рисков с файлом, строкой и доказательством;
3. список проверок, которые стоит запустить.

Решение всегда принимает человек. Помощник не может approve, merge или менять код.

#### Примеры комментария

Хороший:

```text
app/api.py, create_review — обращение payload["diff"] вызывает KeyError,
если в теле запроса нет поля diff. Проверка: отправить POST /api/reviews
с пустым JSON-объектом и проверить ответ сервиса.
```

Плохой:

```text
Код можно улучшить. Добавьте тесты и обработку ошибок.
```

### Запуск 2: тот же diff и master prompt

1. Попросите рабочего агента выполнить новый тестовый запуск OpenCode с той же моделью и настройками.
2. Вход содержит тот же `TRAINING_PR.diff` и согласованный `Master Prompt v1` из `prompts.md` со встроенным Context Pack. Историю рабочего чата тестируемая модель не получает.
3. Агент сохраняет исходный ответ и добавляет строку `P1-02` в журнал.
4. Сравните ответы: ссылки на файл или строку, подтверждение выводов, соблюдение ограничений и воспроизводимость проверок.
5. Сообщите OpenCode свои выводы. Поручите ему записать сравнение в `prompts.md` и внести согласованные исправления в master prompt.

## Домашняя работа и PR

1. Попросите OpenCode завершить обязательные файлы. Проверьте, что требования, решение и тесты согласованы, и передайте агенту замечания.
2. Поручите OpenCode доработать master prompt в `prompts.md`: другой инженер должен суметь повторить задачу по записанным входам, инструкциям и проверкам.
3. Попросите OpenCode выполнить из корня репозитория:

   ```bash
   make install
   make test
   ```

4. После проверки diff поручите OpenCode закоммитить изменения в `practice_01` и отправить ветку в свой форк:

   ```bash
   git add practices/practice_01
   git commit -m "Practice 1"
   git push -u origin practice_01
   ```

5. Откройте PR **в своём форке**: `practice_01 → main`. В GitHub выберите свой репозиторий в обоих полях:

   | Поле PR | Значение |
   |---|---|
   | base repository | ваш форк |
   | base | `main` |
   | head repository | ваш форк |
   | compare | `practice_01` |

   `origin` должен указывать на ваш форк. Не открывайте PR в исходный репозиторий курса. Во вкладке **Files changed** должны быть только материалы первой практики и необходимые изображения.

6. Передайте ссылку ревьюерам курса. Исправления по замечаниям коммитьте в ту же ветку: PR обновится автоматически. Если не согласны с замечанием, объясните причину в комментарии PR. Изменения файлов по замечаниям поручайте OpenCode.
7. После завершения ревью влейте PR в `main` своего форка. Если к началу второй практики ревью ещё идёт, следуйте [инструкции Практики 2](../practice_02/README.md#ветка-для-второй-практики).

Можно оставить учебный кейс или перенести все артефакты на собственный проект. Проблема, diff и Context Pack должны относиться к одному проекту.

## Оценка — 10 баллов

| Что проверяем | Баллы |
|---|---:|
| Обязательная структура файлов и воспроизводимые команды | 1 |
| Контекст AS IS, проблема и измеримые метрики | 2 |
| TO BE, use cases, user stories и план поставки | 2 |
| ADR, архитектурная схема и связность решения | 2 |
| Unit, integration, load и E2E-проверки | 2 |
| `prompts.md`: два запуска, ссылки на результаты и собственная критика | 1 |

Подробная таблица для ревьюеров публикуется вместе с критериями курса.
