# Нагрузочные проверки

| Сценарий | Нагрузка и длительность | Допустимый предел | Что измеряем | Evidence |
|---|---|---|---|---|
| База: POST /api/reviews (малые diff) | 10–15 RPS; 15 мин (2 мин прогрев) | p95 < 400 мс; p99 < 800 мс; 5xx = 0; 4xx ≤ 2% (исключая 413) | Латентность p50/p95/p99, доля 4xx, CPU, память, GC, время БД/очередей, пулы потоков/соединений | Отчёт k6/Locust, срез Grafana/APM, ссылки на трассы |
| Большие diff (проверка 413) | Смешанная нагрузка: 10–15% запросов с diff ≈ 25k; 10–15 RPS; 15 мин | 100% корректных 413 для больших diff; 5xx = 0; p95/p99 для «обычных» не хуже базы более чем на 10% | Доля 413, латентность «обычных» запросов, ошибки, CPU/память | Логи/метрики, отчёт k6/Locust, APM-срез |
| Деградация внешнего LLM | 20 RPS; 10 мин; инъекция задержек 10–12s у 5–10% LLM-вызовов | Пользовательский ответ ≤ 10s; fallback 100% для таймаутов; 5xx = 0; p99 «недеградирующих» ≤ 1500 мс | Таймауты LLM, доля fallback, влияние на p95/p99, глубина очередей/ретраев | Трассинг (LLM-клиент/сервер), метрики таймаутов, APM |
| Soak (устойчивость) | 25–30 RPS; 45–60 мин | Нет утечек памяти; дрейф p95 ≤ 10%; 5xx ≤ 0.1% | Память/GC, тренд латентности, размеры пулов/очередей, открытые соединения/FD | Длительные графики Grafana/APM, отчёт теста |
| Stress ramp (точка насыщения) | Рамп: 5→50 RPS, +5 каждые 3 мин; на каждом шаге прогрев 2 мин | Зафиксирована точка, где p95 > 800 мс или 5xx > 0.1% или очереди растут без стабилизации; поведение без 5xx при 413 | Порог насыщения (RPS), p95/p99 по шагам, рост очередей/ошибок | Отчёт k6/Locust с ramp-скриптом, APM-графики |

Условие включения нагрузочных проверок: запускать при подключении реального LLM-провайдера и согласованных целевых SLO. До этого — ограничиться функциональными/интеграционными тестами и локальными микробенчмарками; для порогов использовать диапазоны и выполнить поиск точки насыщения (stress ramp).
