Две части: **живой прогон API одной командой** (воспроизводимый, вывод приложен) и
**сценарий показа интерфейса** (его нужно снять с экрана).

## Часть 1. Прогон API — запускается одной командой

```bash
cd practices/practice_04/subtracker/backend && ./scripts/dev.sh --seed   # :8000
cd practices/practice_05 && python3 demo/run_demo.py
```

Скрипт заводит **собственного пользователя**, поэтому его можно гонять сколько угодно
раз подряд — демо-данные он не портит. Записанный вывод: `artifacts/demo-api.txt`.

Девять шагов и что каждый доказывает:

| Шаг | Что происходит | Что доказывает |
|---|---|---|
| 1 | новый пользователь, одна подписка Netflix 15.49 руками | исходное состояние |
| 2 | загрузка выписки на 38 строк | импорт создан, **подписок по-прежнему 1** — ничего без подтверждения |
| 3 | два списка кандидатов | 6 основных и 2 «требует проверки»; Netflix помечен `amount_differs` со ссылкой на подписку владельца |
| 4 | исходные строки Netflix | обоснование: видно 15.49 трижды и 17.99 в четвёртый раз |
| 5 | подтверждение: 3 завести, Netflix обновить | у кандидата без совпадения поле `action` **не отправляется** (решение Р2); расход 15.49 → 96.47 |
| 6 | тот же запрос с тем же ключом | HTTP 200, ответ идентичен, подписок столько же — идемпотентность (Р4) |
| 7 | повторная загрузка той же выписки | всё найденное помечено совпадением, дублей не возникает; `DELETE` освобождает слот (Р3) |
| 8 | битые колонки, пустой файл, PDF | `400` / `400` / `415`, в теле только код и параметры — прозы сервер не присылает (Р12) |
| 9 | владелец правит сумму «в другой вкладке» между разбором и подтверждением | **решение Р13**: конфликтный элемент пропущен, остальные применены, правка владельца не затёрта |

Ключевой фрагмент вывода — шаг 9, то самое место, которое мы чинили в контракте:

```
владелец правит подписку #28 в другой вкладке: 15.49 -> 99.99
HTTP 201 · создано 1, не применено 1
  + VPN Service 19.90
  ! confirm.amount_conflict  {'actual_amount': '99.99'}
```

По первой редакции контракта здесь был бы отказ всего импорта — при том что подписка
уже создана.

## Часть 2. Интерфейс — сценарий для записи с экрана

**Запись:** _(вставить ссылку — снимается с экрана, 2–3 минуты)_

### Подготовка

```bash
cd practices/practice_04/subtracker/backend && ./scripts/dev.sh --seed   # :8000
cd practices/practice_04/subtracker/frontend && npm run dev              # :5173
```

Вход: `demo@example.com` / `demo-password`. Файлы для загрузки — в `~/Downloads/`:

- `statement-sample.csv` — опорная выписка из задания, 38 строк;
- `statement-second.csv` — вторая выписка с другими сервисами (Dropbox, Figma с
  подорожанием, Duolingo), на случай если опорная уже импортирована.

### Шаги

1. **«Обзор»** — расход за месяц, список подписок. Назвать число вслух, к нему вернёмся.
2. **Вкладка «Импортировать выписку»** → выбрать файл → «Найти подписки».
3. **Экран подтверждения**, главный кадр:
   - «Нашли подписки» — раскрыто, кандидаты отмечены заранее;
   - «Возможно, подписки» — свёрнуто: VPN Service (цикл по одному интервалу) и
     Github Pro Annual (цикл по слову `ANNUAL` при единственном списании);
   - «Уже есть у вас» — свёрнуто: Spotify (совпал точно) и Netflix (сумма другая);
   - предупреждение «1 из 38 строк не разобрано»;
   - раскрыть обоснование у любого кандидата — видны исходные строки выписки.
4. **Решение по дубликату.** Раскрыть «Уже есть у вас», отметить Netflix, выбрать
   «Обновить мою подписку до 17.99». Видна подпись «У вас 15.49, в выписке 17.99».
5. **Снять галку** с одного кандидата — счётчик и сумма «в месяц по выбранным» меняются.
6. **Подтвердить** → экран итога: создано, обновлено с прежней и новой суммой.
7. **«Обзор»** — расход вырос ровно на ожидаемую величину.
8. **Повторная загрузка того же файла** — всё помечено «уже есть у вас», дублей нет.
9. **Ошибка** — загрузить любой `.pdf`: понятное сообщение, экран остаётся рабочим.
10. **Переключить язык на английский** — все тексты импорта переводятся.

### Что показывает каждый шаг

| Шаг | Что доказывает |
|---|---|
| 3 | три группы строятся только из полей контракта; числовую уверенность клиент не читает |
| 3 | частичный разбор не блокирует работу (Р10) |
| 4 | узкое обновление существующей подписки (Р1) |
| 6 | ответ содержит и созданное, и обновлённое с прежней суммой — на этом держится откат (Р9) |
| 7 | сквозной сценарий целиком |
| 8 | сопоставление защищает от дублей |
| 9 | ошибка приходит кодом, текст собирает клиент (Р12) |
| 10 | оба языка, как требует конституция |

## Что ещё можно показать

**Swagger** на http://localhost:8000/docs — четыре эндпоинта со схемами запроса и
ответа, сгенерированные из кода. По сути контракт в исполняемом виде: видно, что
реализованный API совпадает с тем, о чём договорились две команды.
