# Общий контекст (вставляется в ОБА чата целиком)

Это единственный документ, который обе команды видят одинаково. Всё остальное каждая
команда придумывает сама. Ничего про контракт API здесь намеренно нет.

## Продукт

**subtracker** — трекер личных подписок. Пользователь заводит свои платные сервисы
(стриминг, облака, VPN, приложения), приложение показывает расход за месяц и за год
и предупреждает о ближайших списаниях. Аудитория — физлица с 5–20 подписками.
Подробное ТЗ — `SPEC.md` в корне репозитория.

## Что уже работает

Бэкенд (FastAPI, async SQLAlchemy, PostgreSQL, JWT):
- `POST /api/auth/register`, `/login`, `/refresh`, `GET /api/auth/me`
- `GET/POST/PATCH/DELETE /api/subscriptions`, `GET /api/subscriptions/{id}`
- `GET /api/subscriptions/upcoming?days=N`
- `GET /api/stats/summary`, `GET /api/stats/breakdown`

Фронтенд (React 19 + Vite + TypeScript + Tailwind 4): вход, регистрация, вкладки
«Обзор» и «Подписки», добавление и правка подписки в боковой панели (на телефоне —
нижняя шторка), две темы (по умолчанию тёмная), два языка (ru/en), баннер рекламы
для плана Free.

## Модель подписки (существующая, менять её не нужно)

`id`, `owner_id`, `name` (1–255), `amount` (Decimal > 0, 2 знака),
`billing_cycle` (`monthly` | `yearly` | `weekly` | `custom_days`),
`custom_interval_days` (1–3650, только для `custom_days`), `is_active`,
`start_date`, `next_billing_date` (обе в диапазоне 2000-01-01…2100-12-31),
`note` (до 500 символов, необязательно). Категорий нет. Валюта одна на пользователя
(`default_currency` в профиле).

## Проблема, которую решаем

Чтобы продукт начал приносить пользу, надо завести 5–20 подписок руками. Почти никто
этого не делает: пустой экран после регистрации — главная точка оттока.

## Фича

**Импорт банковской выписки.** Пользователь выгружает из интернет-банка файл с
транзакциями и загружает его в subtracker. Приложение само находит в нём повторяющиеся
списания, похожие на подписки, и предлагает добавить их — пользователь подтверждает
то, что согласен завести.

## Пример выписки

Реальный файл, с которым придётся работать, — `fixtures/statement-sample.csv`.
Колонки: `date`, `description`, `amount`, `currency`. В нём намеренно есть:
повторяющиеся списания с разной периодичностью, подорожание одной подписки,
разовые покупки, перевод и зарплата, сервисы, которые у пользователя уже заведены,
строка с одним-единственным списанием и одна сломанная строка.

## Общие ограничения проекта

- Деньги — только `Decimal`, никогда `float`. Округление до 2 знаков.
- Весь доступ к БД асинхронный, валидация через Pydantic v2, бизнес-логика в
  сервисном слое, не в роутах.
- Поля JSON API — в snake_case; фронт переводит их в camelCase в одном месте, в API-клиенте.
- Изоляция пользователей: видно и меняется только своё.
- Схема БД меняется только миграциями Alembic.
- Каждый новый эндпоинт сопровождается тестом.
- Все пользовательские тексты — через словарь переводов, ru и en.

## Что вне рамок

Банковские API и OAuth-подключение к банку, OCR и PDF, импорт из писем,
платные фичи плана Pro, фоновые воркеры и очереди задач, уведомления.
Только файл, который пользователь загрузил руками.
