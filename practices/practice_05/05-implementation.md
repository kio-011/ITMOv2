# Шаг 9 — реализация (5 из 10 баллов)

**Где:** код проекта — `practices/practice_04/subtracker`, ветка `practice_05`.
Изоляция здесь уже не нужна: обе спеки согласованы, работаем в одном чате над всем проектом.

Spec Kit для реализации ставится в корень проекта, отдельно от папок команд:

```bash
cd practices/practice_04/subtracker
uvx --from git+https://github.com/github/spec-kit.git \
  specify init --here --force --non-interactive --integration claude --script sh
```

Папки `team-ui/` и `team-logic/` трогать не нужно: их `.specify/` остаются как
сдаточные артефакты — по ним видно, что каждая команда работала у себя.

**Вход:** `practices/practice_05/artifacts/contract.md` и обе спеки из
`practices/practice_05/artifacts/after/`.

## 9а. План

Сложи обе согласованные спеки в одну фичу Spec Kit и дальше иди штатным путём:

```
/speckit-plan
```

Аргументом — следующее:

> Реализуем по приложенному контракту и двум согласованным спецификациям.
> Стек задан и не обсуждается: бэкенд — FastAPI, async SQLAlchemy 2.x, PostgreSQL,
> Pydantic v2, Alembic, pytest; фронт — React 19, Vite, TypeScript strict, Tailwind 4,
> Vitest, Testing Library. Конвенции — в `AGENTS.md`.
> План должен покрывать обе стороны и явно обозначить точку стыковки: до неё
> серверная и клиентская части делаются независимо, после — проверяются вместе.
> Отдельным пунктом — какие тесты доказывают, что контракт соблюдён с обеих сторон.

Затем:
```
/speckit-tasks
/speckit-analyze
```

`/speckit-analyze` здесь важен: это штатная проверка Spec Kit на согласованность
спеки, плана и задач. Её результат — материал для сравнения с OpenSpec, где такой
команды нет. Сохрани вывод в `artifacts/analyze-output.md`.

## 9в. Обязательные проверки

Слайд требует именно их, без них 5 баллов не закрыть.

**Сквозной сценарий.** Один тест, проходящий путь целиком: загрузка
`shared/fixtures/statement-sample.csv` → разбор → снятие галки хотя бы с одного кандидата →
подтверждение → подписки появились у пользователя → сумма за месяц на «Обзоре»
выросла ровно на ожидаемую величину. Проверить и автотестом, и руками.

**Ошибка.** Файл не того формата или битый: пользователь видит понятное сообщение,
ничего не сохранилось, состояние приложения не поехало.

**Граница.** Как минимум два случая из списка, подтверждённые тестами:
- `GITHUB INC PRO ANNUAL` — одна строка, в кандидаты не попадает;
- `SALARY ACME CORP` — идеально периодичный приход, не подписка;
- `SPOTIFY` — уже заведён, помечен как дубликат, при подтверждении не задваивается;
- `BROKEN ROW NO AMOUNT` — одна строка не разобралась, остальные 37 обработаны;
- повторное подтверждение того же импорта не создаёт вторые подписки.

**Зелёная сборка.** `cd backend && uv run pytest && uv run ruff check .`,
`cd frontend && npm run lint && npm run build && npm test`. Вывод — в
`artifacts/checks.txt`.
