# Few-shot

- Артефакт Практики 1: practices/practice_01/tests_load.md — план нагрузочного тестирования.
- Что хотим улучшить: воспроизводимость (инструмент и режим нагрузки), профиль трафика и данные, Pass/Fail-гейты с числовыми порогами, observability и evidence (конкретные метрики/дашборды), описание инъекций деградации LLM, явные допущения и источники, параметры запуска (SEED/BASE_URL/think time).

## Примеры

### Хороший результат

Чёткая структура, численные пороги и воспроизводимость. Числа — плейсхолдеры; замени на ваши значения или пометь как допущение.

```md
## Профиль трафика
- Размеры diff: <PCT_SMALL>% ≤ <SMALL_SIZE>, <PCT_MEDIUM>% — <MEDIUM_RANGE>, <PCT_LARGE>% — ≈ <LARGE_SIZE> (кейс 413)
- Think time: <THINK_TIME> ± <THINK_JITTER>
- Прогрев: <WARMUP_DURATION> (метрики не учитываются)

## Инструменты и запуск
- Инструмент: <TOOL> (<LOAD_MODE>)
- ENV: BASE_URL, SEED=<SEED>, BIG_DIFF_PCT=<PCT_LARGE>
- Запуск: <RUN_COMMAND>

## Pass/Fail Gate
- База: p95 < <P95_LIMIT>; p99 < <P99_LIMIT>; 5xx = 0; 4xx ≤ <FOUR_XX_LIMIT> (искл. 413)
- Большие diff: 413 = 100% для больших; 5xx = 0; влияние на «обычные» ≤ +<IMPACT_LIMIT>% к p95/p99
- Деградация LLM: инъекции <INJECT_PCT>% с <INJECT_DELAY>; ответ ≤ <USER_RESP_LIMIT>; p99 недеградирующих ≤ <P99_NODEG_LIMIT>; 5xx = 0
- Soak: дрейф p95 ≤ <SOAK_DRIFT_LIMIT>%; память без тренда > <MEM_DRIFT_LIMIT>%/час; 5xx ≤ <SOAK_5XX_LIMIT>%
- Stress ramp: точка насыщения при p95 > <RAMP_P95_LIMIT> или 5xx > <RAMP_5XX_LIMIT>% или рост очередей без стабилизации

## Observability и evidence
- Метрики: http_server_duration_*; llm_client_duration_*; process_resident_memory_bytes; process_cpu_seconds_total; queue_depth/retries_total
- Дашборды: Latency percentiles; Error rates; LLM client latency; CPU/Mem/GC; Queues/Threads/Conns
- Evidence: summary JSON; 3 трассы на p95; скриншоты дашбордов за окна измерений

## Инъекции
- Метод: локальный мок/прокси (например, toxiproxy) или фича‑флаг; таймауты клиента/сервера задокументированы

## Допущения и источники
- Пороговые SLO: источник — ADR/problem.md или помечены как допущение с TODO на сбор данных
```

### Плохой результат

Размыто, без числовых порогов, без способа воспроизведения:

Сделаем много запросов на /api/reviews и посмотрим, выдержит ли. Если будет медленно — увеличим ресурсы. Инструмент любой. Скрины метрик — по возможности.
