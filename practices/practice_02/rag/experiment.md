## Запрос

Суть: отвечать только из явно перечисленных источников. Никакого web, никаких «вспомнила». Обязательно каждый свой шаг и каждое утверждение объясняй ссылкой на источник.

Инструкции для выполнения:

1. Сбор фактов
   - Прочитай «Разрешённые источники» и выпиши факты, относящиеся к нагрузочному тестированию: SLO/пороги, сценарии нагрузки, правила безопасности/наблюдаемости/границ (SEC-1, API-1, REL-1, OUT-1, SCOPE-1, QA-1, OBS-1), архитектурные ограничения, пользовательские сценарии, технический контекст.
   - Для каждого факта оформи таблицу: Fact | Source | Citation | Quote.
     - Source: точный путь файла из списка выше.
     - Citation: раздел/подраздел или идентификатор правила (например, API-1); для diff — формат `file:line`.
     - Quote: короткая цитата (1–2 строки) из источника.

2. Сопоставление с текущим tests_load.md
   - Сравни текущее содержание `practices/practice_01/tests_load.md` с собранными фактами.
   - Где есть прямое подтверждение — отметь «подтверждено» и приложи ссылку (Source + Citation).
   - Где данных нет в источниках — отметь «допущение». Не подставляй числа/параметры из головы.

3. Предложения по правкам tests_load.md (строго в пределах источников)
   - Разрешено:
     - Добавлять пометки «допущение» там, где источника нет.
     - Переформулировать на более проверяемые формулировки (без изменения чисел), если это помогает связать с правилами из `CASE.md` или метриками из `problem.md`.

   - Запрещено:
     - Придумывать новые числовые пороги, распределения, длительности или инструменты, если они не подтверждены источниками.

4. Формат результата
   - Блок «Проект изменений tests_load.md»: список точечных правок с адресацией «строка/раздел → новая формулировка» и ссылками на источники под каждое изменение. Если номер строки неизвестен, привяжи к заголовку/табличной строке.
   - Блок «Список допущений и дефицита данных»: таблица «Что | Почему это допущение | Какой источник требуется собрать».
   - Блок «Evidence»: консолидированный список цитат/ссылок на источники, подтверждающих изменения.

5. Сохранение артефакта результата
   - Запиши полный текст блока улчешенного `tests_load.md` в файл:
