# Нагрузочные проверки

| Сценарий | Нагрузка и длительность | Допустимые пороги | Что измеряем | Evidence |
|---|---|---|---|---|
| База: POST /api/reviews (малые diff) | 10-15 RPS, 15 мин (2 мин прогрев) | p50 < 150-250 мс; p95 < 400-600 мс; p99 < 800-1200 мс; 5xx = 0; 4xx <= 0.5% и только валидные | Латентность p50/p95/p99, доля 4xx/5xx; системные: CPU, память, GC, пул соединений, задержки БД | Отчет k6/Locust (percentiles), Grafana/APM срез, 5-10 трасс p99 |
| Большие diff (проверка 413) | Смешанная нагрузка 20-25 RPS, 12-15 мин (2 мин прогрев); 10-15% запросов с diff ~ 25k, остальные - малые | 100% больших diff -> HTTP 413; 5xx = 0; общая 4xx за счет 413 <= 15%; для валидных малых diff: p95 < 500-700 мс, p99 < 1-1.2 с | Доля/частота 413; разделенная латентность (малые vs большие diff); стабильность очередей/БД/пулов | k6/Locust с тегами (тип diff), логи и метрики 413, Grafana/APM |
| Деградация LLM (таймаут и fallback) | 20 RPS, 10 мин (1-2 мин прогрев); инъекция задержек 10-12s у 5-10% LLM-вызовов | Для деградирующих вызовов: пользовательский ответ <= 10s за счет таймаута LLM и fallback; доля fallback = 100%; 5xx = 0; общая доля запросов > 10s = 0 | Таймауты LLM, доля fallback, влияние на p95/p99; пулы соединений/потоков, очереди, внешние вызовы | Трассинг деградирующих запросов, k6/Locust тайминги, Grafana/APM алерты |
| Soak (длительный прогон) | 25-30 RPS, 45-60 мин (5 мин прогрев) | Нет утечек памяти; дрейф p95 <= 10%; 5xx <= 0.1%; GC-паузы стабильны; steady-state CPU < 70-80% | RSS/heap, GC, латентность во времени, пулы соединений, очереди/БД, открытые дескрипторы | Длительные графики Grafana/APM, итоговый k6/Locust отчет, профили heap/alloc (при наличии) |
| Стресс-рампа (точка насыщения) | Рамп 5 -> 60 RPS, шаг +5 RPS каждые 2 мин до устойчивого роста p99/ошибок | Точка насыщения: RPS, при котором p99 > 2x от базового либо 5xx >= 1%; 413 на больших diff считаются валидными | Кривая p95/p99 vs RPS, error rate 5xx, загрузка CPU/БД/очередей, лимиты пулов | График "RPS vs p95/p99 и ошибки", фиксация точки насыщения в отчете |

Условие включения нагрузочных проверок: запускаем при подключении реального LLM-провайдера и согласованных SLO по POST `/api/reviews`. До этого этапа ограничиваемся функциональными и интеграционными тестами плюс локальным микролодом для проверки базовой стабилизации.

## Как использовали AI

- Этот план сгенерирован и откалиброван на основе запроса practices/practice_02/rctf/experiment.md.
