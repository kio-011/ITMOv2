## 2. Модель и обоснование выбора

| Параметр | Значение |
|---|---|
| ID в API | `qwen3.5-9b-mlx` |
| Файл | `lmstudio-community/Qwen3.5-9B-MLX-4bit` |
| Параметры | 9B, архитектура `qwen3_5` |
| **Квантизация** | **MLX 4-bit** |
| Вес на диске | 5.98 ГБ |
| Контекст при загрузке | 32 768 токенов |
| Параллельных слотов | 4 |

Также доступны локально: `Qwen3.5-4B-MLX-4bit` (3.06 ГБ) и эмбеддер `nomic-embed-text-v1.5`.

### Почему такой выбор

- **MLX, а не GGUF** — родной бэкенд Apple Silicon: вычисления идут через Metal по unified memory, без копирования между CPU и GPU.
- **9B, а не 4B** — запас качества на вопросах-ловушках, где модель должна заметить отсутствие ответа в репозитории или ложную предпосылку. 5.98 ГБ оставляют достаточный резерв от 16 ГБ под KV-кэш и систему.
- **4-bit** — компромисс между качеством и памятью. 8-битная версия 9B (~9.5 ГБ) с контекстом 32k подошла бы к пределу памяти вплотную.
- **Контекст 32k, а не 64k** — измеренная деградация скорости (§4) делает длинный контекст бесполезным: модель не успеет его обработать за разумное время. 32k достаточно для агентного цикла по подмножеству файлов проекта.

## 3. Пригодность к агентной работе

Tool calling проверен прямым запросом к `/v1/chat/completions` с двумя объявленными инструментами:

```
finish_reason: "tool_calls"
tool_calls[0]: read_file({"path": "Makefile"})
prompt=384  completion=62 (reasoning 34)  wall=6.2 с
```

Модель выбрала корректный инструмент и аргумент вместо того, чтобы выдумать содержимое файла. Агентный режим OpenCode с правами `read/glob/grep` применим.

## 5. Ограничения и выводы

**Размышления неотключаемы и стоят 97% токенов.** На типовом вопросе 1 434 токена рассуждений против 48 токенов ответа — минута на трёхстрочный ответ по файлу в девять строк. Отключить через OpenAI-эндпоинт нельзя. Вывод: не бороться, а закладывать в бюджет. Reasoning повышает шанс, что модель заметит отсутствие ответа или ложную предпосылку, то есть работает именно там, где проверка критична.

**Малый лимит вывода даёт пустые ответы, а не плохие.** При `max_tokens=200` модель вернула `content: "\n\n"` — весь бюджет ушёл в размышление. Технический обрыв внешне неотличим от отказа отвечать. Поэтому вместе с каждым ответом сохраняется `finish_reason`, и `length` трактуется как несостоявшийся прогон, а не как результат.

**Скорость падает в разы с ростом контекста.** 24.7 tok/s при 220 токенах против 3.7 при 7 700. В агентном цикле контекст накапливается с каждым прочитанным файлом, поэтому модели подаются точечные файлы, а `.venv`, `.ruff_cache` и `.pytest_cache` исключаются из области чтения.

**Рассинхрон длины контекста.** Исходный `opencode.json` заявлял `context: 65536`, фактически модель загружена с 32 768. OpenCode собрал бы промпт под 64k, LM Studio молча обрезал бы его. Приведено к 32 768.

**Системного Python не хватало для `make test`.** В `lab/Makefile` стоит проверка Python 3.10+, а в macOS поставляется 3.9.6 — падала только проверка версии, сами тесты были зелёными. Решено установкой `python@3.13` через Homebrew (3.13.16).

Результат: `Standard library only: ready`, 3 passed.

## 6. Конфигурация

### Modelfile

Ollama не используется, поэтому `Modelfile` и `Modelfile.agent` ведутся как декларативная запись фактической конфигурации, с комментарием о соответствии параметрам LM Studio. Оба приведены к реально загруженной модели:

| Параметр | Было | Стало | Почему |
|---|---|---|---|
| `FROM` | `qwen3.5:4b` | `qwen3.5-9b-mlx` | запущена 9B, а не 4B |
| `num_ctx` | 4096 / 65536 | 32768 / 32768 | под реальную длину контекста при загрузке |
| `num_predict` | не задан | 8192 | reasoning съедает 1400–2000 токенов до начала ответа |

В `Modelfile.agent` блок `SYSTEM` отсутствует намеренно: промпт агента приходит от OpenCode из `demo/repo-system.txt`, зашитый `SYSTEM` конфликтовал бы с ним.

### Тестовые прогоны OpenCode

`lab/demo/opencode.json` настроен так:

- провайдер `lmstudio` → `http://127.0.0.1:1234/v1`, модель `qwen3.5-9b-mlx`;
- `limit`: `context: 32768`, `output: 8192` — под реальную загрузку и под расход токенов на reasoning;
- `model` и `small_model` на одном ID — чтобы служебные запросы не ушли в облако и не подгрузили вторую модель;
- агент `local-guide` с правами `"*": "deny"` + `read`/`glob`/`grep` — ограничение на чтение;
- `default_agent: "local-guide"` — чтобы случайный запуск в этой папке не оказался в режиме Build с `edit` и `bash`;
- провайдер VseLLM в этом файле отсутствует намеренно: облачный доступ нужен только рабочему агенту и остаётся в корневом `opencode.json`.

## 7. Отклонения от методички

| Методичка | Реализовано | Почему |
|---|---|---|
| Ollama + `Modelfile` | LM Studio + параметры загрузки | согласовано с преподавателем |
| `num_ctx` в `Modelfile` | длина контекста при загрузке модели | прямой аналог |
| `SYSTEM` в `Modelfile` | `system.txt` / `repo-system.txt` | промпт подаётся клиентом |

Параметры `Modelfile` сохраняются как декларативная запись конфигурации; соответствие настройкам LM Studio — в таблице выше.

4 из 5 по существу верны, обе обязательные ловушки пройдены. В среднем 50 с на вопрос.

**Главное наблюдение: узкое место — стратегия поиска, а не знания модели.** На вопросе о CI перебор десяти точных путей к конфигам дал безупречный ответ. На вопросе о запуске тестов единственный глоб `**/*test*` увёл мимо `Makefile`, где ответ записан дословно, — и модель ответила по тому файлу, который успела прочитать. Инструменты отработали штатно; ошибка в том, как модель ими распорядилась.

**Методическое замечание.** Первый прогон забракован: каталог с ответами находился внутри песочницы, и на Q3 модель прочитала собственный лог. Изоляция восстановлена — вывод вынесен за пределы песочницы, песочница пересоздаётся перед каждым вопросом. Все пять вопросов перезапущены с нуля.
